紙の本（PDF）と電子書籍（EPUB）を同じCSSで作る時に、つまずきやすい点をまとめる。

## 1. 縦書きの向き

CSSの論理プロパティは、文字の流れに沿った向きで指定する。縦書き（`vertical-rl`）では次のとおり。

| 指定 | 横書き | 縦書き |
| --- | --- | --- |
| `*-block-start` | 上 | 右 |
| `*-block-end` | 下 | 左 |
| `*-inline-start` | 左 | 上（天） |
| `*-inline-end` | 右 | 下（地） |
| `inline-size` | 幅 | 高さ |
| `text-align` | 左右の揃え | **天地の揃え** |

- 見出しに `text-align: center` を付けると、天地の中央に寄る。天から書き始めるには `start`。
- 見出しの「天からの位置」は `margin-inline-start`（または `text-indent`）、左右の空きは `margin-block-*`。
- Kindleは論理プロパティを一部解釈しない為、EPUBには後処理で物理プロパティを補う（`kindle.md`）。
- 縦書きの本の中の図版・表は、横書きにする事が多い（theme-bunko は `figure` を横書きにしている）。後処理の `--horizontal figure` はこの為。

## 2. ルビ

VFMの書き方は `{漢字|よみ}`。

- **生のHTMLの段落の中では変換されない。** 段落が `<p>` `<div>` `<blockquote>` 等のブロックのタグで始まると、VFMはその段落を丸ごとHTMLとして通す為、中の `{漢字|よみ}` は記号のまま出る。その中では `<ruby>漢字<rt>よみ</rt></ruby>` と書く。`<ruby>` や `<span>` で始まる段落は普通の段落なので変換される。
- 見出しの直後に空行を入れずに `{…|…}` で始まる段落を書くと、HTMLが壊れる。見出しの後は空行を入れる。
- 機械的にルビを足す時、既にルビのある所に重ねない（`{{漢字|よみ}|よみ}`）。
- 以上は `check_ruby_syntax.py` で検査できる（ビルドの前処理に入れる）。
- **モノルビ**（1字ずつ）は `{東|とう}{京|きょう}`、**グループルビ**（語全体）は `{東京|とうきょう}`。熟語で、読みの区切りが字と対応する物はモノルビの方が改行に強い（グループルビの語は行末で分割されない）。
- 原稿が「漢字（よみ）」の括弧書きで来た時、どれをルビにするかは著者に確かめる。括弧書きのまま残す読み（初出だけ「百足（むかで）」のように本文として読ませたい物）もある。
- ルビ付きの行は行間が広がる事がある。ページの行数が揃わない時は、行の高さ（`line-height`）に余裕を持たせる。
- Word に書き出す時、pandoc はルビを落とす。`build_word.py` を使う。

## 3. 圏点・傍線

- 圏点（傍点）は `text-emphasis: filled sesame;`（縦書きの標準は「﹅」ゴマ）。横書きは `filled dot` が一般的。
- 傍線は `text-decoration: underline;`。縦書きで線を左右どちらに引くかは `text-underline-position: right`／`left` で指定する。
- Kindleでの表示を必ず確かめる。

## 4. 縦中横・縦書きの英数字

- 2〜3桁の数字は縦中横にする：`<span class="tcy">12</span>` と `.tcy { text-combine-upright: all; }`。4桁以上（年号等）は、漢数字にするか、1字ずつ縦に並べる（全角数字）。
- Kindleは縦中横の中が5文字以上だと警告を出す（`::before` の中身も数える）。
- 英単語は既定で横倒しになる（`text-orientation: mixed`）。略語（「NHK」等）を立てるなら全角にするか `text-orientation: upright` の範囲を作る。

## 5. 約物と禁則

- 行頭に「、」「。」「）」等が来ない、行末に「（」が来ない、といった禁則は、ブラウザ（Chrome）の既定で概ね処理される。より厳しくするなら `line-break: strict`。
- 括弧の連続（「）（」）の詰めは `text-spacing-trim` で調整できる（Chrome）。紙と電子で結果が違う事がある。
- 約物だけを別の書体にする（`@font-face` の `unicode-range`）方法は、Kindleで効かない（`kindle.md`）。
- 原稿の「…」「―」は2つ続けて使う（「……」「――」）のが慣例。「―」と「ー」「－」の取り違えに注意。

## 6. 改ページ・右ページ始まり

- 章を新しいページから始める：`break-before: page`。奇数ページ（表側のページ）から：`break-before: recto`（必要なら白紙が入る）。
- `right`・`left` は紙面の物理的な右・左。縦書き（右綴じ）では奇数ページが左にある為、`right` は**偶数ページ**になる（Vivliostyle 11.2で確認）。章を奇数ページから始めたいなら、書字方向に関わらず `recto` を使う。実際のPDFのノンブルで確かめる。
- 中身の無い `div` に `break-before: right` を付けて白紙を入れる方法は、電子書籍では意味が無い。`@media print` の中に書く。

## 7. 柱・ノンブル・版面

- 柱（章の名前）とノンブル（ページ番号）は `@page` の余白の領域（`@top-left`・`@bottom-center` 等）に `content: env(doc-title)`・`counter(page)` で出す。テーマが変数で用意している事が多い（theme-bunko: `--vs-theme--page-top-left-content` 等）。
- 扉・白紙のページで柱とノンブルを消すには、名前付きのページ（`@page blank { … }` と `.blank { page: blank; }`）。
- 版面（文字の入る範囲）＝ 判型 − 余白。1行の字数 ＝ 版面の幅（縦書きは高さ）÷ 文字サイズ、行数 ＝ 版面の高さ（縦書きは幅）÷（文字サイズ×行間）。目標の字数・行数から余白を逆算すると決めやすい。
- のど（綴じる側）の余白は、ページ数が多いほど広く取る（KDPのペーパーバックは、151〜300ページで12.7mm以上等の決まりがある）。

## 8. 紙と電子書籍の書き分け

同じCSSを共有する為、紙のページの大きさを前提にした値は `@media print { … }` に入れる。

- pt・mm固定の位置・幅・高さ、`inline-size`
- ページの中央に置く為の計算（扉の題名等）
- 空要素での改ページ・白紙
- 奥付の枠の大きさ

電子書籍は、読者が文字の大きさや画面の向きを変える。固定の値を入れると、画面からはみ出したり、不自然な空白ができたりする。`@media print` の外には、em 等の相対的な指定だけを書く。

## 9. 泣き別れ

本来一緒にあるべき物が、ページや行で分かれてしまう事。

- 見出しがページの最後に残る → 見出しに `break-after: avoid`（すべての階層に）
- 段落の1行だけがページの頭・終わりに分かれる → `widows: 2; orphans: 2`（既定）。ページの行数を揃えたい本では、1行の泣き別れを許す事もある（方針を決める）
- 図と説明文が分かれる → `figure { break-inside: avoid }`
- 表がページをまたぐ → 見出しの行（`thead`）を繰り返す。Markdownの表の1行目が見出しの行になる
- 段落の最後の行が1〜2文字 → その段落だけ字間をわずかに詰める・広げる、または文を手直し（著者と相談）。`text-wrap: pretty` は効かない事が多い（Vivliostyle 11.2で、本全体では減らなかった）。内容が固まってから直す
- 数字と単位、「……」「――」は、Chrome（Vivliostyle）が既定で分けない。分けたくない語は `white-space: nowrap`
- `check_layout.py` でPDFから候補を探せる

## 10. ページ番号の数え方

- 修正依頼の「P.42」は、ページに印刷されたノンブル。PDFビューアの「42ページ目」（通し番号）とは、表紙・目次・扉の分ずれる。報告や依頼の照合はノンブルで行う。
- `pdf_diff_pages.py` は、変わったページを通し番号とノンブルの両方で出す。
