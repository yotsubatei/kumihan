# KDPへの入稿でつまずく所（Kindle電子書籍）

KDPのサーバーの変換は、epubcheck や Kindle Previewer より厳しい。手元で通っても、KDPで落ちる事がある。
Vivliostyle で作った2冊（横書きの技術書・縦書きの読み物）で、実際に出会ったエラーと直し方。
後処理（雛形の package.json の postbuild）に、下の道具はすべて入っている。

## エラーと原因（症状から引く）

| KDPのエラー | 原因 | 直す道具 |
| --- | --- | --- |
| 「このファイルの拡張子は現在サポートされていません」 | ペーパーバックの原稿の欄に EPUB・KPF を上げている | 電子書籍の「電子書籍の原稿」の欄から上げる |
| プレビューで変換エラー、保存できない（変換ログのボタンが反応しない事も） | EPUBの中の画像のファイル名・manifest のIDが日本語 | `epub_ascii_names.py` |
| 「目次に壊れているリンクがあります」 | 見出しのIDが日本語で、目次のリンクが%エンコード。ランドマークの目次のリンクが `#toc`（Kindleの変換で nav が消える） | `epub_ascii_names.py`（本文のIDも。CSSの `#ID` の指定も書き換える）、`epub_toc_plain.py`（ランドマーク） |
| 「HTMLファイルをKindleフォーマットに変換できませんでした」 | 本文に入力フォームの部品（チェックリストの `<input type="checkbox">`） | `epub_strip_forms.py` |
| 「Kindle 変換で内部エラーが発生しました」 | **テーマ（theme-base の basic.css）の段組（`columns` 等）と、引用・図・コード・表の `writing-mode: unset`。** 本文が増えると落ちる | `epub_kindle_safe_css.py`（変数の解決の後に） |

念のために入れている直し（それだけでは内部エラーは消えなかったが、KDPの受け付けやすい形に寄せる）：
テーマのCSSを1つにまとめる（`epub_flatten_css.py`）、SVGの画像をPNGに（`epub_svg_to_png.py`）、
書体を使っている文字だけに絞る（`epub_subset_fonts.py`。古い書体の mort 等の表も落ちる）、
紙の本だけの書体を電子書籍に入れない、前処理で書体のフォルダを毎回空にする。

## 上げる前に確かめる事

- epubcheck 0件、Kindle Previewer で Enhanced Typesetting 対応、変換ログの「注意」も0件（W14001 等のリンクの注意はKDPでエラーになる）
- EPUBの中に、日本語のファイル名・ID、SVGの画像、`<input>`、`writing-mode: unset`、`columns` が残っていない
- KDPの本の言語が「日本語」（EPUBの dc:language と合わせる）
- KPF ではなく EPUB を上げる

## 原因の分からないエラーの切り分け（二分探索）

1. KDPに試験用の下書きの本を1冊作る（本番の本には上げない）
2. 数行だけの小さなEPUB（pandoc で作れる）を上げる。落ちるならKDP側の不具合、通るなら本の中身
3. 書式あり・なし、本文の前半・後半、書式のファイル（テーマ／本の独自）、テーマの部品の組、宣言の種類…と、
   1回で候補が半分になるように外したEPUBを作って上げる。AIが試験用のEPUBを作り、人は上げて結果を伝える
4. 本書の内部エラーは、10回ほどで「書字方向と段組の指定」に絞り込めた

## 変換ログ

- 「変換ログをダウンロード」が反応しない時は、別のブラウザで、ポップアップとダウンロードを許可して押す
- 内部エラーのログは「担当チームが対応、3営業日以内にメール」とだけ書かれ、原因は出ない。何度も上げ直さず、切り分けるかメールを待つ
